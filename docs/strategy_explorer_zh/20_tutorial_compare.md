# 教程：Compare

Compare 使用相同的共用 GUI，但数据源因版本而异：

- PB7 回测成交、**PBGui Simulation** 和 **PB7 Backtest Engine**
- **Stored PB8 Result** 和 **Fresh PB8 Replay**

---

## 1) 从结果开始（推荐）

1. 打开 PB7 或 PB8 **Backtest Results**。
2. 选择一个结果并点击 **Strategy Explorer**。

你也可以从 **Pareto Explorer** 打开一个 PB8 候选项。PB8 Run 和 PB8 Backtest 提供直接的配置传递，但只有结果传递会为 **Stored PB8 Result vs Fresh PB8 Replay** 提供已保存结果来源信息。

如果要比较两个 PB8 Pareto 候选项，请先选择第一个候选项并点击 **Pin Explorer Baseline**。然后从同一结果中选择另一个候选项并点击 **Strategy Explorer**。不需要结果路径；与所有者绑定的草稿会携带两个配置，Compare 会将它们标记为当前配置和固定基准。基准仅属于当前页面，结果发生变化或页面重新加载时会被清除。引用的覆盖配置文件缺失时，会阻止传递，而不是忽略问题。

对于 PB8，经过身份验证的传递会在服务器端保存已验证的结果位置，并使用与所有者绑定的不透明草稿 ID 打开 Strategy Explorer。结果路径不会放入浏览器页面或 URL。

---

## 2) 开始 Compare

1. 打开 **Compare**。
2. PB7 用户选择现有的某一种 PB7 比较模式。
3. PB8 结果用户选择 **Stored PB8 Result vs Fresh PB8 Replay**。两个候选项的 Pareto 传递使用同一面板执行重放 A 与重放 B 的比较。
4. 对于已保存的 PB8 结果，PBGui 会自动从所选币种第一条已保存成交前一根 K 线开始重放。将 **Compare max candles** 设置得足够大，以便达到你想比较的最后一条成交。
5. 点击 **Start Compare**。

PB8 Compare 会读取传递的已保存结果中的有边界成交，并根据传递的配置执行一次新的有边界原生重放。已保存成交会先按所选币种和精确的新重放窗口过滤，然后才应用成交/订单数量限制，因此更早的或窗口外的成交不会占用限制。Compare 使用成交记录，不会重建精确的历史挂单。

它会拒绝没有来源的比较或运行时完全相同的比较。当时间戳处于配置的容差范围内（默认 1,000 ms）、订单类型匹配，并且价格与数量解析为相同的原生交易所步进时，成交才会匹配。文件顺序不用于确定成交身份。出现可见的覆盖不完整警告，表示配置的 K 线数量限制没有达到最后一条已保存成交。

解读提示：

- 仅已保存或仅新重放中的成交，可能表示配置、市场、开始时间、数据或引擎版本存在差异。
- 仅已保存或仅新重放中的行，表示另一侧不存在满足以下条件的事件：在时间戳容差内、订单类型相同、经过交易所量化的价格和数量相同。
- 匹配的成交只能验证这次有边界的重放比较，不能验证未来的实时账户行为。

---

## 3) 典型调试工作流

1. 确认 **Exchange** 和 **Coin** 相同。
2. 确认已保存成交的时间戳与所选重放窗口存在重叠。
3. 确认传递的配置和币种覆盖配置是预期的版本。
4. 开启 **Mismatches only** 运行 Compare；需要匹配上下文时再关闭它。
5. 使用 Movie Builder 检查 K 线和成交；不要期待 PB8 提供历史的每帧理想订单梯级。
