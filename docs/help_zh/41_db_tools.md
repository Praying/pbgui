# DB Tools

DB Tools 为 PBGui 数据库、仪表板定义和模板提供受控维护与单向迁移工作流，覆盖本地 Master 和已知远程 Master。从 **System -> DB Tools** 打开。

每次数据库写入都会先创建备份。破坏性操作要求显式预览或确认，远程操作使用 VPS Manager 中已配置的主机。

## 目标与安全

- **local** 是页面打开所在的 PBGui 安装。
- 远程目标是来自 VPS Manager 的已知 Master 节点。
- 复制和同步操作的源与目标必须不同。
- 无法安全更改受影响目标时，PBData 写入活动可以阻止操作。
- 数据库替换和恢复会停止目标上的 PBData，移除过期的 SQLite WAL/SHM 附属文件，安装文件，并在操作前 PBData 正在运行时重启它。
- 长时间运行的操作出现在进度面板中，也可以通过 DB Tools 日志查看器检查。

附着的 DB Tools 操作运行时，不要关闭或重启 API 服务器。操作完成前，重启控件会报告阻止项。

## 清理用户数据

Cleanup 从单个目标上的 `pbgui.db` 和 `pbgui_trades.db` 移除属于所选用户的行。

1. 选择目标 Master。
2. 选择 **Remove all data for users** 或 **Remove data older than date**。
3. 选择一个或多个用户。
4. 单击 **Preview** 并按数据库和表验证行数。
5. 只在预览符合你的意图后单击 **Run Cleanup**。

日期模式从带时间戳列的表中移除早于 UTC 截止时间的行。更改目标、模式、日期或选择后，需要新的预览。

## 复制用户数据

Copy User Data 在两个 Master 之间传输所选用户。

| 模式 | 行为 |
|---|---|
| **Add only missing** | 插入目标上缺失的行，并保留现有目标行。 |
| **Replace user data** | 先删除所选用户在目标上的行，然后导入其源行。 |

复制前始终预览。预览检查源用户、目标安全和预期操作。Replace 模式有意对目标上所选用户具有破坏性。

## 复制完整数据库

此操作用源 Master 的文件替换目标上的 `pbgui.db` 和 `pbgui_trades.db`。

只在目标应成为源的完整数据库副本时使用。操作：

1. 验证源和目标，
2. 暂存一致的源快照，
3. 创建目标备份，
4. 需要时停止目标 PBData，
5. 安装两个数据库并移除过期附属文件，
6. 如果之前正在运行，重启 PBData。

只需要传输特定用户时，优先使用 Copy User Data 或 Sync Jobs。

## 同步任务

Sync Jobs 定期将一个源 Master 的所选用户复制到一个或多个目标。

- 同步是从配置的源到每个所选目标的单向。
- 任务只添加缺失行；它们从不删除或覆盖现有目标行。
- 每次运行在写入前创建目标备份。
- 最小间隔为 30 秒。
- PBData 正在为所选用户积极写入数据时，目标会被跳过或阻止。

推荐设置：

1. 创建任务并给它一个清晰的源到目标名称。
2. 选择一个源、至少一个目标和要复制的用户。
3. 运行 **Check Safety**。
4. 使用 **Run Now** 进行初始受控运行。
5. 查看进度和日志。
6. 只在手动运行成功后启用任务。

保存的已启用任务在 API 重启后重建。分离的同步运行是独立任务，通过其持久化的任务状态和日志保持可见。

## 备份管理器

Backup Manager 列出 DB Tools 为一个 Master 创建的备份。排序或选择行以恢复或删除文件。

Restore 在替换任何数据库前执行另一次安全备份。它停止 PBData、安装所选备份、移除过期的 SQLite 附属文件，并在适当时重启 PBData。

Delete 永久移除所选备份文件。删除旧副本前，至少保留一个已验证的近期备份。

## 仪表板

Dashboards 在 Master 之间复制仪表板 JSON 文件和仪表板模板 JSON 文件。

| 模式 | 行为 |
|---|---|
| **Add only missing** | 创建目标上不存在的条目，跳过现有名称。 |
| **Replace all selected** | 替换现有所选条目并创建缺失条目。 |

替换前备份现有文件。开始复制前，预览所选仪表板、模板、源、目标和模式。

## 故障排除

- **目标不可用**：验证 VPS Manager 中的主机和 SSH 状态。
- **安全检查被阻止**：停止或等待报告的 PBData 写入者，然后再次运行检查。
- **操作已在运行**：等待活动 DB Tools 任务完成，并检查其进度或日志。
- **同步任务跳过目标**：打开任务日志，检查 PBData 活动、用户可用性和目标连通性。
- **恢复或复制失败**：不要盲目重试。先检查日志并验证自动创建的目标备份存在。

## 最佳实践

1. 预览每次手动写入并确认源和目标名称。
2. 必须保留现有目标数据时，从 **Add only missing** 开始。
3. 在启用调度前用 **Run Now** 测试同步任务。
4. 保留近期备份，直到更改的目标已验证。
5. 避免对同一目标同时进行维护操作。
