# AI Chat

## 用途

AI Chat 是第一个实用的 PBGui AI 集成。它将提供商聊天与受控的 PBGui 能力相结合。

代理可以列出并读取 PB7/PB8 优化器配置、优化器运行摘要、回测摘要和动态优化器元数据。它不能读取日志、凭据、任意文件、检查点或原始结果产物。

代理还可以对对话中已经可用的有界 JSON 提出普通 Python 分析。PBGui 从该输入中移除机密和主机路径命名的字段，在批准前显示确切脚本和净化后的 JSON，并且在所有者显式批准对话与摘要绑定的提案前不运行任何内容。

对于 Passivbot 问题，代理可以从确切安装的 PB7/PB8 检出中搜索文档和源文件。结果包括已安装的 Git 提交、相对路径、行范围，以及检出使用官方 Passivbot 仓库时的官方提交固定 GitHub 链接。源码检查仅文本：PBGui 从不执行、导入或修改被检查的代码。

对于 PB8，它可以验证完整优化器配置，并提出保存它、保存并排队新配置或排队现有配置。仅排队不会启动优化器。对于显式启动请求，助手可以列出无路径的 PB8 队列 ID，并提议在一次单独审查的操作中立即启动最多四个确切的排队任务。这些工具只创建提案。PBGui 显示确切操作并要求在执行前显式批准。PB7 变更保持禁用，因为其当前队列快照尚未满足所需的不可变性和并发保证。

跨版本比较保留其实际运行时。PB7-trailing 与 PB8-`trailing_martingale` 的请求使用真实的 PB7 源配置和单独的 PB8 配置；PBGui 不会静默地用 PB8 的 `trailing_grid_v7` 兼容策略替换 PB7 侧。助手可以读取 PB7 源并准备 PB8 侧，但 PB7 变更、排队和启动在 PB7 批准边界安全前保持手动。

ChatGPT 运行时在私有空工作区中启动，本地执行、网络搜索、记忆、多代理和 MCP 工具被禁用。只有 PBGui 动态能力命名空间可用。任何命令或文件更改请求都会被拒绝。

已批准的 Python 分析是单独的失败关闭能力。它通过 Bubblewrap 在空临时工作区中运行，带只读 Python 运行时和可用时安装的 NumPy/Pandas 等库。它具有隔离的网络命名空间，没有主机 home、PBGui 数据、凭据或其他主机文件，净化环境、JSON 标准输入、有界标准输出/错误、资源限制和短超时。Bubblewrap 或资源限制不可用时，PBGui 绝不回退到非沙箱执行。

## ChatGPT

ChatGPT 使用 PBGui 附带的官方 Codex 登录。

1. PBGui 和浏览器运行在同一台计算机上时选择 **Browser login**。
2. 打开显示的 HTTPS 地址。
3. 完成正常的 ChatGPT 浏览器授权。
4. 等待 PBGui 报告 ChatGPT 已连接。
5. 选择账户可见的模型并发送消息。

对于远程或无头 PBGui 主机，改为选择 **Device code**。设备登录要求设备代码授权在 ChatGPT 安全设置中启用，并要求你输入显示的一次性代码。

PBGui 不为此连接使用 OpenAI Platform API 密钥。可用模型和限制取决于连接的 ChatGPT 账户。
模型选择器从 Codex `model/list` 动态加载；PBGui 不维护固定的 ChatGPT 模型列表。

## OpenCode Zen 和 Go

OpenCode Zen 和 OpenCode Go 使用同一个 OpenCode 工作区密钥。Zen 包括变化的免费和按量付费模型；Go 增加订阅模型和包含用量。

OpenCode 提供商卡片包含 **Get OpenCode Go**，通过 PBGui 推荐链接打开订阅页面。这是联盟式推荐：在 OpenCode 当前计划下，邀请者和新订阅者可能获得账户信用。订阅条款和推荐奖励由 OpenCode 控制，可能变化。

1. 在 OpenCode 账户控制台创建或复制密钥。
2. 在 OpenCode 卡片中输入它并选择 **Connect**。
3. PBGui 验证密钥并将其存储在仅所有者可访问的服务器端文件中。
4. 选择可用模型并发送消息。

PBGui 在 Responses、Chat Completions 和 Messages 端点中支持两个目录。可用 ID 来自实时 Zen/Go 目录；名称、协议、成本和限制来自 OpenCode 的实时模型元数据。免费模型从零成本检测，显示在最前并标记 **Free**。新模型使用受支持协议时自动出现，移除的模型消失。可能使用提示和响应进行训练的贡献者模型被明确标记。

**Check free models** 排队串行后台可用性检查。最新所有者特定状态显示在模型旁边，不禁用手动重试。训练选择加入的模型绝不自动探测。

PBGui 能力工具在 OpenCode Chat Completions、OpenAI Responses 和 Anthropic Messages 中使用各协议的原生工具调用契约。PBGui 只在实时模型元数据宣告工具调用支持时启用它们。支持工具的选项标记 **PBGui tools**；明确缺乏它的模型保持标记 **Chat only**。

宣告推理变体的模型显示 **Effort** 选择器。**Standard** 不发送覆盖并保持提供商默认值。所有其他选择按提供商顺序来自所选模型，因此名称各异，可能包括 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`、`ultra` 或提供商特定名称。PBGui 不添加固定变体列表。

标记 **Chat only** 的模型不能检查已安装的 Passivbot 文档、源码或当前 PBGui 数据。它们不接收能力规则或工具名称，直接根据通用知识回答。答案需要本地或已安装运行时证据时，选择标记 **PBGui tools** 的模型。Responses 和 Messages 模型现在可以通过其原生函数结果格式携带已安装版本、文档和源码结果，而不暴露不受限制的文件系统访问。

## 操作批准

PBGui 将可逆浏览器操作与持久操作分开。选择 Pareto 候选的显式请求可以通过类型化、所有者绑定的浏览器操作直接标记打开的 Optimize 页面中确切运行绑定的行。页面还可以为其实体宣告可复用操作。例如，`show_log` 将所选或运行中的 Optimize 和 Backtest 任务或活动机器人配置映射到每个页面现有的日志查看器函数，而不是要求功能特定的模型工具或 Python 分析。操作可以针对另一个已注册的 PBGui 页面：PBGui 导航到那里，自动恢复当前对话，在目标数据加载时保持操作待处理，并且只在目标页面验证确切实体并调用其注册回调后确认它。共享桥不能执行模型生成的 JavaScript、任意 URL、路径或 DOM 选择器。

PBGui 还清点当前可见的非敏感控件，如按钮、同源链接、文本字段、复选框和选择框。每个控件接收一个不透明的短生命周期 ID 及其允许的 `activate` 或 `set_value` 操作。因此助手可以使用普通 PBGui 控件，包括关闭浮动日志窗口，而无需功能特定操作。密码、文件、凭据、令牌、会话、Cookie 和其他敏感控件被省略；字段值绝不复制到此清点中。现有确认对话框和提案批准边界仍然有效。模型工作时提案审查保持隐藏，只在匹配的助手回答完成后出现。批准的操作完成后，PBGui 自动恢复同一助手工作流，因此任何剩余的请求步骤都可以产生自己的审查。

用户确认批准或拒绝后，提案卡片立即消失，PBGui 执行服务器端决策。可见的 applying/rejecting 状态替换它；请求失败时，卡片返回且控件启用，以便安全审查或重试操作。

明确无歧义的可逆命令，如显示唯一可用的日志、关闭可见日志窗口，或显式单击一个唯一命名的可见控件，使用本地浏览器快速路径。PBGui 立即执行操作，在所有者绑定的对话中记录用户请求和完成，并且不联系所选 AI 提供商。有歧义、分析性或变更性请求继续通过正常模型和批准流程。

全局抽屉在所有者作用域的服务器偏好中保持其宽度和打开/关闭状态。因此普通 PBGui 页面导航后，如果之前打开，它会自动重新打开，而显式折叠保持关闭。宽度拖动使用临时的浏览器范围护盾，因此 Dashboard iframe 组件不能窃取鼠标事件，延迟的初始偏好响应不能重置已进行的拖动。

"Stable" 对优化器选择有规范含义：平滑上升的策略权益曲线，低波动性和指数拟合误差，浅回撤，短水下/恢复期，以及强 Sharpe/Sortino。"Stable with good profit" 使用均衡预设，稳定度 60%，利润 40%，因此不需要澄清。真正冲突的目标、缺失的硬限制或未解决的资源确实需要澄清时，PBGui 呈现 2-5 个可点击的快速回复，而不是问卷。零严格匹配绝不授权自动阈值放宽：完整运行替代方案单独返回，并且必须经过其中一个确认才能被选择或排队。

代理提出 PB8 保存/排队操作、Pareto 候选按交易所回测矩阵、仪表板创建/编辑或 Python 分析时，PBGui 在完整页面和抽屉中显示批准卡片。对于 Python，卡片显示确切代码、净化输入、输入摘要和负载摘要。回测提案显示每个候选、交易所、总任务数以及队列自动启动是否可以立即开始。仪表板提案可以使用模板或自由语义布局，带 1-10 行、1-2 列、组件放置、用户、期间、图表模式、组件选项、高度和 Orders-to-Positions 链接。现有仪表板可以逐单元格读取和更改，同时保留无关设置；审查后仪表板发生变化时批准失败。**Review & approve** 打开共享的 PBGui 确认对话框；只有该确切的所有者、对话和摘要绑定负载可以运行。拒绝或关闭对话框不改变任何内容。恢复对话时和每次批准或拒绝后，PBGui 从服务器刷新待处理提案，因此过期或已解决的卡片不被视为当前。

批准的 Pareto 回测矩阵从 Optimize 排队后，PBGui 直接导航到 PB8 Backtest Queue，使新创建的任务及其当前状态无需另一次手动页面更改即可见。

待处理审查保留七天，并在 API 重启后存活。批准仍会重新验证当前配置摘要，因此过期提案不能覆盖预览创建后更改的配置。

Python stdout 在可能时作为严格 JSON 返回，否则作为有界文本。有界 stderr、退出状态、超时状态和截断随结果显示。对于自定义优化器范围计算，代理可以将 Python 直接绑定到优化器运行资源：PBGui 将每个 Pareto 候选及其净化指标解析到沙箱 stdin，而不通过模型工具参数发送完整数据集。审查显示确切代码加资源、候选数、字节大小和数据集摘要。普通加权最小/最大排名可以使用原生完整运行排名工具，它也扫描每个候选，避免从截断的 200 行预览得出结论。

显式批准后，Python 还可以在 `/workspace/pbgui_data`、`/workspace/pb7` 和 `/workspace/pb8` 接收只读挂载。普通文件、数据集、数据库、配置、优化器/回测产物、源码和 `data/logs` 下的文件可以直接读取，无需复制到模型参数中。凭据/API 密钥/令牌/密码/会话/Cookie/SSH/私钥/证书路径、`.env`、Git 元数据、虚拟环境和每个符号链接总是被屏蔽。挂载根目录不可写，沙箱仍然没有网络访问。提案决策和结果使用现有的仅所有者持久操作历史。Python 分析是一次性的，而不是重启阻止项：优雅关闭取消并收割它，而非优雅中断的运行记录为已中断，绝不重放。

连接尝试后，密钥从浏览器清除。PBGui 从不显示已存储的密钥。

## 对话

对话和完成的消息存储在仅所有者可访问的服务器端历史中。完整 AI Chat 页面和全局抽屉使用同一个对话列表。选择历史项会恢复其消息、上次使用的提供商、模型、推理力度、运行状态、错误和待处理提案。提供商、模型和力度可以在回合之间自由更改，而无需创建新对话；需要新的有状态提供商线程时，PBGui 提供有界 transcript，使所选模型可以从现有上下文继续。**New chat** 显式准备另一个对话而不删除较旧历史。**Delete** 使用显式 PBGui 对话框并只移除所选对话。顶部导航中的全局 AI 按钮在每个经过身份验证的顶层 PBGui 页面上打开可折叠的右侧抽屉；完整页面保持可用于提供商设置和更大会话。

在桌面上，拖动抽屉左边缘可将其从紧凑可用宽度调整到完整浏览器视口。PBGui 将宽度存储为仅所有者服务器端偏好，并在其他页面和后续会话中恢复。较小的浏览器窗口暂时将保存的宽度限制到可用视口。移动布局保持全宽，无论保存的桌面宽度如何。

从任一界面开始的回合由 API 拥有，而不是浏览器请求。导航到另一个 PBGui 页面、关闭完整页面、切换对话、开始新聊天或折叠抽屉不会停止回合。两个界面都通过持久对话快照重新连接；只有 **Stop** 取消活动工作。API 重启时，未完成的工作标记为已中断，绝不自动重放。

每条消息提供 **Copy**。用户消息还提供 **Rewind**，它持久地移除该消息和所有后续响应，拒绝移除分支的待处理提案，重置提供商上下文，保留抽屉中当前选择的提供商/模型，并将提示恢复到编辑器供编辑或重新发送。

提案审查使用红/绿字段差异而不是原始 JSON。移除值前缀 `-`，新值前缀 `+`，更改的配置路径显示在上方。Review 和 raw JSON 窗格可以垂直调整大小；Reject 和 Review & approve 保持在粘性页脚中可见。

回合失败且其提示仍在当前浏览器页面可用时，**Retry** 重新提交确切提示。PBGui 有意不单独存储失败的提示，因此稍后恢复的页面显示错误，但不会猜测早期提示或提供可能重复已完成请求的不安全重试。

抽屉可以包含小的结构化页面上下文：页面键、匹配的帮助主题、当前分区、显式注册的资源引用和可选聚焦字段。Run 编辑器的 Passivbot 日志面板打开时，最多 120 行当前可见行作为有界、凭据编辑的摘录包含在内，使常规机器人状态问题不需要 Python 提案。Optimize Pareto 上下文按名称、Pareto 数和修改时间戳标识当前打开的运行，并包含最多当前标记的候选名称，因此"回测这三个"等后续请求保留可见选择。上下文芯片显示创建新对话前将附加什么。上下文和日志摘录是不可信数据，绝不授予额外访问。生产页面通过 `PBGuiAI.registerPageContext()` 注册所选配置、仪表板、币种、交易所、主机、分区和显式允许列表的非敏感聚焦字段。

PBGui 不抓取任意页面文本、表格、表单、URL 或浏览器存储。共享上下文边界拒绝凭据、密码、令牌、API 密钥、私钥、会话、Cookie、SSH、机密和通用日志字段。唯一的日志例外是上面显式的有界 Passivbot 摘录，它在发送前在浏览器和 API 中都被编辑。API Keys 和 Logging 只暴露非机密的用户身份或分区。

开始新的用户回合会拒绝先前分支中任何仍待处理的提案。在提出不同问题前批准或拒绝提案；这防止旧审查的操作在新对话状态下恢复。已批准操作成功但其自动 AI 后续超时时，PBGui 分别报告操作完成和后续失败。

对于上下文帮助，代理可以读取或搜索规范的英文/德文 PBGui 指南，然后在实现细节相关时使用现有已安装的 Passivbot 文档/源码工具。

响应运行时，状态行显示经过的时间和安全的活动标签，如文档搜索或源码阅读。工具参数、提供商推理、提示和结果不会在该状态中暴露。选择 **Stop** 取消活动提供商请求。

活动和重试控件出现在聊天底部编辑器旁边。OpenAI Responses 模型提供显式推理摘要时，PBGui 存储并显示在折叠的 **Reasoning summary** 分区中。隐藏或加密的思维链从不暴露。

`high`、`xhigh`、`max` 或 `ultra` 等推理变体在出现任何答案文本前可能花费几分钟处理工具结果。PBGui 能力完成后，状态从工具操作变为 **model is processing results**，因此缓慢的推理阶段不会被误认为是卡住的本地搜索。PBGui 在有界截止时间内未完成的回合会停止，并报告正常超时错误。

## 隐私

消息和启用的页面上下文发送到所选外部提供商。对话历史由 PBGui 私下存储，但提示和响应不会写入运维日志。发送敏感信息前，查看提供商当前的隐私、保留和订阅条款。

## 故障排除

- **Runtime missing（运行时缺失）：** 安装包含 `openai-codex-cli-bin` 的 PBGui 依赖并重启 API 服务。
- **Browser login 回调失败：** 浏览器登录要求浏览器和 PBGui API 运行在同一台计算机上；远程主机使用 Device code。
- **Device login 不可用：** 需要时在 ChatGPT 账户安全设置中启用设备代码登录。
- **Authentication failed（身份验证失败）：** 重新连接提供商并验证订阅或密钥。
- **Usage limit reached（达到用量限制）：** 等待提供商限制重置或选择另一个已连接提供商。
- **所选模型当前不可用：** 模型被宣告但没有健康的上游容量；选择另一个模型稍后重试。
- **支持工具的回答需要多次请求：** 每个能力结果必须返回给无状态模型。PBGui 将此限制为三轮能力，然后从收集的结果请求最终回答。
- **Python 分析沙箱不可用：** 在 PBGui 主机上安装 Bubblewrap 和 `prlimit`。PBGui 有意不提供非沙箱回退。
- **Python 分析超时或输出被截断：** 请求更小的输入、更简单的计算或更紧凑的 JSON 结果。
- **ChatGPT 停留在 model is processing results：** 更高的推理力度在本地工具完成后合法地需要更长时间。结果不再值得等待时选择 **Stop**，或使用 Standard 或模型支持的较低力度开始新聊天。
- **没有受支持的模型：** 连接后刷新，并确认 OpenCode 账户当前在 Zen 或 Go 实时目录中暴露模型。
