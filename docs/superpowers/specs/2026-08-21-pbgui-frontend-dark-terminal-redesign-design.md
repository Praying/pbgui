# PBGui 前端深色专业交易终端重设计

日期：2026-08-21  
状态：已获用户批准（设计对话）

## 背景与目标

PBGui 当前前端是 Vue 3 + TypeScript + Vite 的多页面应用，同时保留 legacy HTML fallback。项目已有共享设计 tokens、基础样式和组件样式，但不同页面仍需要统一的页面外框、导航行为、信息层级和异步状态体验。

本设计将现有前端统一为 **深色专业交易终端**，重点服务运行、回测、优化、监控、日志和配置等长时间操作场景。目标是提升信息层级、工作区效率、响应式体验和视觉一致性，同时保持现有业务功能、路由、API、国际化和关键测试契约不变。

## 已确认的设计决策

| 决策点 | 选择 |
|---|---|
| 视觉定位 | 深色专业交易终端 |
| 产品结构 | Hybrid control room |
| 桌面导航 | 可收缩工作区侧栏（Collapsible workbench rail） |
| 信息密度 | 平衡型：突出核心数据，次要信息分层展示 |
| 色彩 | 冷调深色莫兰迪 + 高可读语义状态色 |
| 实施策略 | 共享基础先行，再按页面族分批迁移 |
| 技术策略 | 保留 Vue、TypeScript、Vite、vue-i18n、API 和现有测试体系 |
| 离线约束 | 不引入 CDN 字体、远程脚本或其他 hosted asset |

## 范围与边界

### 范围内

- 统一 Vue 页面使用的视觉 tokens、基础页面壳和共享组件。
- 引入可展开/收缩的工作区侧栏和统一的 active 页面状态。
- 统一页面标题区、状态摘要、主操作、辅助操作和滚动区域。
- 统一面板、指标、表格、筛选栏、表单分组、提示、空状态、加载和错误状态。
- 统一桌面、中等宽度和窄屏布局规则。
- 按页面族逐步迁移现有 Vue 页面。
- 对 legacy fallback 页面进行必要的视觉同步，避免 fallback 与 Vue 页面产生明显断层。
- 保持英文与简体中文翻译 key 对齐，并审查受影响的帮助文档。

### 范围外

- 不重写业务 API、服务端接口或数据模型。
- 不改变策略、运行、回测、优化、图表计算和日志处理逻辑。
- 不重写页面路由和导航映射语义。
- 不随意修改 dashboard editor 的冻结 CSS 文件及其 parity 契约。
- 不将 legacy 层重新建设成第二套独立设计系统。
- 不添加未被需求要求的新业务功能、主题切换或远程资源依赖。

## 架构设计

### 技术与入口

继续沿用当前多页面 Vue 结构：每个页面由自己的 `index.html`、`main.ts` 和 `App.vue` 组成，并按现有顺序加载：

```text
tokens.css -> base.css -> components.css -> page-local styles
```

业务数据流、boot 配置、共享 API 客户端、国际化和导航路由保持现状。设计改造集中在共享表现层和页面局部样式。

### 统一 Terminal Shell

新增或整理共享页面壳，负责以下职责：

- 可收缩工作区侧栏。
- 当前页面和页面族 active 状态。
- 页面顶部标题、上下文信息和操作区域。
- 全局连接状态、服务状态、帮助、语言和账户入口。
- 页面主体最大宽度、留白、滚动和层级。
- 响应式断点和窄屏导航行为。
- 键盘焦点、语义结构和 reduced-motion 行为。

页面自身只提供标题、说明、页面级操作以及业务面板、表格、表单、图表或日志内容；不在每页重复实现导航和页面外框。

共享边界建议如下：

```text
AppShell
├── WorkbenchRail
├── WorkspaceHeader
│   ├── Breadcrumb / page family
│   ├── Page title and description
│   ├── Status summary
│   └── Primary and secondary actions
└── WorkspaceContent
    ├── SummaryStrip
    ├── Main work area
    └── Supporting panels / activity
```

共享组件只定义稳定的视觉和交互契约，不承载具体页面业务逻辑。

## 视觉系统

### 色彩

采用冷调、低饱和的深色莫兰迪方向。莫兰迪色用于页面背景、工作区、面板、边界和主强调色；成功、警告、错误等语义状态保留更高可读性，不能因为降低饱和度而失去识别能力。

色彩层级：

- 页面背景：深蓝灰、墨灰，不使用纯黑。
- 工作区：比页面背景略亮的灰蓝。
- 面板：通过表面层级、间距和少量边界建立分组。
- 主强调：灰调冰蓝或雾蓝，仅使用一个主色系。
- 成功：柔和青绿。
- 警告：灰调琥珀。
- 错误：灰调砖红。
- 文字：冷白主文字、蓝灰次文字和更低对比的辅助文字。

设计基调可参考以下方向，最终值集中维护在 `frontend/src/styles/tokens.css`，页面 CSS 不散落重复颜色：

```text
页面背景   #10171f
工作区     #151e28
面板       #1b2631
边界       #2a3946
主强调     #7fa9bd
成功       #7fae9b
警告       #c0a277
错误       #bd8585
主文字     #d8e0e5
次文字     #8d9ba5
```

以上值是视觉基准，不是要求所有组件机械使用的最终常量；对比度、状态识别和现有兼容别名必须在实现时验证。

### 字体与数字

- 使用已有的离线系统字体栈，不加载 CDN 字体。
- 页面标题使用有辨识度的无衬线字体；正文保持清晰紧凑。
- 表格、价格、收益率、时间和指标启用 tabular numerals。
- 日志、配置片段和技术标识使用等宽字体。
- 标题采用 sentence case，避免所有标题统一大写。
- 正文和说明限制最大宽度，避免长段落横跨整个工作区。

### 表面、深度和布局

- 面板优先通过背景层级和留白分组，不给每个元素同时添加边框、阴影和白色背景。
- 细微冷色边界用于必要分隔；浮层、弹窗和高优先级操作才使用明显 elevation。
- 工作区容器使用较柔和圆角，内部控件使用更紧凑圆角。
- 页面不强制使用三等分卡片行；按内容选择主区/辅助区、不对称双栏、表格优先、图表/事件流或表单/预览布局。
- 页面使用受约束的最大宽度和明确滚动区域，不让宽屏内容无限拉伸。
- 大标题使用紧凑 tracking 和 balance；数据数字使用等宽或 tabular 视觉。

## 统一图标系统

按钮、菜单、导航和状态提示统一采用 **Phosphor Icons**，通过 npm 本地依赖和按需导入构建进前端产物，不使用 CDN。默认使用 **Regular** 线条风格，避免混用 emoji、文字符号、不同图标库和不一致的内联 SVG。

图标尺寸规则：

| 场景 | 尺寸与规则 |
|---|---|
| WorkbenchRail | 20px；收缩时保留图标，并提供 tooltip 和完整可访问名称 |
| 带文字的一级按钮 | 16px；图标位于文字左侧 |
| 紧凑操作按钮与菜单项 | 16px |
| 纯图标按钮 | 18px；必须设置 `aria-label`，并提供 tooltip |
| 状态提示 | 16px；必须搭配状态文字，不只通过颜色或图标传达含义 |
| 空状态和错误状态 | 24-32px；可使用更有表现力的 Duotone，但同一状态块保持一致 |
| 图表工具栏 | 16px；默认低对比，hover 和 focus 后增强 |

使用规则：

- 默认使用同一描边体系的 Regular 图标；只有空状态、错误状态等独立状态块可使用 Duotone。
- 只在图标能提高操作识别速度时使用；不为每个按钮机械添加图标。
- 图标颜色继承文字或语义色，不使用额外多色渐变图标。
- 导航与菜单 active 状态由图标、文字、背景或边线共同表达，不把图标或颜色作为唯一提示。
- 所有图标按钮必须支持键盘焦点、具有可访问名称，并在收缩或仅图标状态提供 tooltip。
- 保留图表、交易对标识等业务视觉；不强制将所有产品图形替换为通用线性图标。
- 迁移时以共享导航中的 emoji HTML entity 和页面中不一致的 SVG/文本图标为优先替换范围，不因图标升级改变路由或业务行为。

## 导航与交互

### WorkbenchRail

展开状态显示页面分组、页面名称和 active 状态；分组可以展开和收起。侧栏顶部显示 PBGui 品牌和连接状态，底部保留帮助、语言和账户入口。

收缩状态只保留稳定图标和当前状态：

- 使用 tooltip、`aria-label` 和可访问名称补足完整页面名称。
- 当前页面通过背景、边线和文字/图标同时表达，不只依赖颜色。
- 展开/收缩状态通过本地持久化恢复。
- 键盘可以切换侧栏并访问导航项。
- 动画使用 transform、opacity 或合适的 CSS grid track 变化，并响应 `prefers-reduced-motion`。

### 操作反馈

- 按钮和链接有 200ms 左右的平滑状态变化，不使用瞬时跳变。
- 按下时提供轻微 pressed feedback，避免过度缩放。
- 所有可聚焦元素保留明显的 focus-visible ring。
- 弹层通过明确操作关闭，不以 backdrop click 作为唯一关闭方式。
- 不引入 `window.alert()` 或新的 native confirmation。

## 响应式规范

### 宽屏桌面

- 显示完整可收缩侧栏。
- 主工作区使用更宽内容区域。
- 图表、表格和配置区可以并排显示。
- 辅助信息放到右侧或下方，不压缩主任务区域。

### 中等宽度

- 侧栏默认收缩。
- 页面标题区保留主要操作，次要操作进入 action menu。
- 双栏逐步转为上下结构。
- 表格允许横向滚动，不把关键数字压缩到不可读。

### 窄屏

- 侧栏转为可展开 overlay/drawer，而不是永久占用内容宽度。
- 页面主体改为单列。
- 指标条横向滚动或分组折叠。
- 表单按逻辑分段。
- 关键操作放在容易触达的位置，但不遮挡内容。
- 大型表格按列优先级提供隐藏或简化策略。

## 页面状态与文案

所有有异步行为的页面必须显式处理：

```text
正常：连接状态 + 最近更新时间
进行中：操作名称 + 进度或处理中提示
空数据：当前没有数据 + 下一步动作
警告：影响范围 + 建议操作
错误：具体原因 + 重试或返回路径
```

规则：

- 初始加载使用贴合页面结构的 skeleton，不使用无上下文通用 spinner。
- 错误在页面内显示，不使用 alert。
- 成功消息简短、具体且不使用感叹号。
- 使用主动语态和具体操作，例如“Connection failed. Try again.”。
- 英文和简体中文字典 key 保持对齐。
- 受影响的导航标题、页面说明和帮助文档必须同步审查。
- 空状态必须说明当前状态并提供下一步动作，而不是显示空白页面。

## 可访问性、元信息与资源约束

- 保留并验证 skip-to-content。
- 统一 focus-visible 样式和合理 tab 顺序。
- 语义状态同时通过文字、图标或结构表达，不只依赖颜色。
- 使用语义 HTML，如 `nav`、`main`、`section`、`article` 和 `aside`。
- 有意义的图片保留准确 alt 文本；本次设计不新增远程图片依赖。
- 保持现有 z-index 层级，新增层级必须落在既有 scale 中。
- 页面保留正确的 title、description 和必要 social meta 信息。
- 不引入 CDN 字体、远程脚本、远程地图或无法离线工作的资源。

## 验证计划

每个页面族完成后执行：

```bash
cd frontend

```

共享壳和迁移页面需要重点验证：

- 侧栏展开、收缩、active 状态和键盘操作。
- 刷新后导航状态恢复。
- 中英文切换及字典 key 对齐。
- 连接、加载、空数据、警告和错误状态。
- 宽屏、中等宽度和窄屏布局。
- `prefers-reduced-motion`。
- 页面路由和帮助映射没有断链。
- dashboard editor 冻结 CSS parity 测试保持通过。
- legacy fallback 在 Vue 构建不可用时仍可加载并保持可用。

## 验收标准

本次统一重设计完成的标准是：

1. Vue 页面使用一致的深色冷调莫兰迪视觉层级和统一页面壳。
2. 桌面端可以展开/收缩工作区侧栏，收缩后仍能识别并访问当前页面。
3. 主要工作台、运维、数据工具和辅助页面均按页面族迁移完成，且没有重复实现导航外框。
4. 核心数据、状态、错误和空状态在各页面有明确的视觉和文案反馈。
5. 中等宽度和窄屏布局不会出现内容溢出、关键操作遮挡或不可读数据。
6. 按钮、菜单和导航使用一致的 Phosphor Icons 图标语言；纯图标操作提供可访问名称和 tooltip。
7. 现有功能、API、路由、国际化、帮助覆盖和冻结 CSS 契约不被破坏。
8. `npm test`、`npm run typecheck` 和 `npm run build` 在每个迁移阶段及最终状态通过。
